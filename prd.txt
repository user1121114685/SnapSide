# 桌面图标移动到副屏 PRD

## 1. 项目概述

### 1.1 项目名称
IconMover（暂定名）

### 1.2 项目定位
一个基于 C++/Win32 原生开发的 Windows 桌面托盘工具，用于在多显示器场景下，将 Windows 桌面图标自动或手动移动到目标显示器，并保持与系统桌面图标排列逻辑一致。

### 1.3 项目背景
在双屏或多屏办公场景中，部分用户希望将桌面图标集中摆放到副屏，以便主屏保持干净、适合演示、录屏或专注工作。Windows 原生系统并未提供“将所有桌面图标自动迁移到指定显示器”的直接功能，因此需要一个轻量、稳定、常驻后台的桌面工具，监听显示器变化并自动完成图标重排。

本项目为全新 C++/Win32 原生桌面工具，从零开始构建，不涉及旧代码迁移或兼容历史架构。

---

## 2. 产品目标

### 2.1 核心目标
1. 程序启动后自动等待 Explorer 桌面 `ListView` 就绪，并自动执行一次桌面图标移动。
2. 自动识别显示器拓扑结构，在多显示器环境下将全部桌面图标移动到目标显示器。
3. 图标在目标显示器工作区左上角开始，按列优先方式平铺，且尽量与系统图标网格间距一致。
4. 监听显示器变化事件，在分辨率、显示器连接状态、主副屏关系变化后自动重新执行图标移动。
5. 提供托盘交互入口，支持手动立即移动、设置目标显示器、开机自启开关和退出。
6. 关键操作和失败原因写入日志文件，便于问题定位。

### 2.2 业务价值
1. 提升多屏办公场景下的桌面整理效率。
2. 减少用户手工拖动桌面图标的操作成本。
3. 在显示器频繁插拔、远程办公、扩展坞切换等场景中保持桌面图标布局可控。

---

## 3. 适用范围

### 3.1 目标用户
1. 使用 Windows 10 及以上系统的多显示器办公用户。
2. 希望主屏保持整洁、将桌面图标集中到副屏的用户。
3. 需要开机自动恢复图标布局的用户。

### 3.2 系统环境
1. Windows 10 及以上。
2. x64 平台。
3. Explorer 作为系统桌面外壳正常运行。
4. 支持 Visual Studio 2019/2022 + MSVC 构建。

2. 开机自启设置与状态持久化。

## 6. 功能需求列表

## 6.1 程序启动与常驻

### 功能说明
程序启动后不弹主窗口，初始化日志、配置、托盘图标和消息循环，等待 Explorer 桌面 `ListView` 就绪；就绪后自动执行一次图标移动。

### 用户价值
用户无需手动操作，开机后自动恢复预期桌面布局。

### 实现要求
1. 程序启动后创建隐藏消息窗口，负责接收托盘、自定义消息和系统广播消息。
2. 初始化托盘图标与右键菜单。
3. 启动后台轮询或定时检查，等待 Explorer 桌面 `SysListView32` 出现。
4. 发现 `SysListView32` 后，执行一次移动逻辑。
5. 若 Explorer 长时间未就绪，持续重试并写日志，不崩溃退出。

### 相关 Win32 / Shell API
1. `FindWindow("Progman", NULL)`
2. `FindWindowEx`
3. `Shell_NotifyIcon`
4. 自定义 `WM_TRAYICON`
5. `CreateWindowEx` / 消息循环
6. `SetTimer` 或等效轮询机制

### 实现思路
1. 通过 `FindWindow("Progman")` 获取桌面宿主窗口。
2. 通过多层 `FindWindowEx` 定位到承载桌面图标的 `SysListView32`。
3. Explorer 未就绪时，通过定时器定期重试。
4. 一旦找到目标 `ListView`，停止等待定时器，进入图标移动流程。

---

## 6.2 开机自启动

### 功能说明
支持用户通过托盘菜单开启或关闭开机自启。程序使用当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 实现，不需要管理员权限。

### 用户价值
保证每次登录系统后自动恢复桌面图标布局。

### 实现要求
1. 托盘菜单显示当前开机自启状态。
2. 用户点击后即时写入或删除注册表项。
3. 写入后立即刷新内存状态和菜单勾选状态。
4. 写入失败时记录日志并提示失败状态。

### 相关 Win32 API
1. `RegOpenKeyEx`
2. `RegSetValueEx`
3. `RegDeleteValue`
4. `RegQueryValueEx`

### 实现思路
1. 启动时读取 `Run` 项判断是否已启用自启。
2. 菜单点击触发写入可执行文件完整路径。
3. 关闭自启时删除对应键值。
4. 所有注册表失败统一通过 `GetLastError() + FormatMessage` 记录日志。

---

## 6.3 显示器枚举与目标显示器识别

### 功能说明
程序需枚举所有显示器，识别主显示器与可用副显示器，默认将桌面图标移动到副屏；同时支持通过托盘菜单设置目标显示器。

### 用户价值
适配双屏、多屏、扩展坞切换等实际环境。

### 实现要求
1. 启动时枚举所有显示器并建立显示器列表。
2. 默认目标显示器为第一个非主显示器。
3. 当存在多个非主显示器时，允许用户从托盘菜单中选择目标显示器。
4. 若保存的目标显示器当前不存在，则自动降级到第一个可用非主显示器。
5. 若当前仅有一个显示器，则不执行移动，仅记录日志。

### 相关 Win32 API
1. `EnumDisplayMonitors`
2. `GetMonitorInfo`
3. `GetSystemMetrics(SM_CMONITORS)`
4. `GetSystemMetrics(SM_XVIRTUALSCREEN)`
5. `GetSystemMetrics(SM_YVIRTUALSCREEN)`
6. `GetSystemMetrics(SM_CXVIRTUALSCREEN)`
7. `GetSystemMetrics(SM_CYVIRTUALSCREEN)`

### 实现思路
1. 使用 `EnumDisplayMonitors` 枚举每个显示器句柄和矩形区域。
2. 通过 `MONITORINFOEX` 判断 `MONITORINFOF_PRIMARY`，识别主显示器。
3. 记录每个显示器在虚拟屏幕坐标系中的位置、尺寸、工作区信息、设备名。
4. 默认使用首个非主显示器作为目标；菜单中展示显示器序号与主/副标识。

---

## 6.4 目标显示器工作区计算

### 功能说明
图标必须从目标显示器“工作区”左上角开始排列，而不是整个显示器物理区域左上角，避免与任务栏等系统保留区域重叠。

### 用户价值
保证图标排列不遮挡任务栏，布局更符合用户预期。

### 实现要求
1. 以目标显示器对应工作区为图标摆放区域。
2. 工作区坐标统一映射到虚拟屏幕坐标系下使用。
3. 图标位置计算必须支持副屏位于主屏左侧、右侧、上方、下方等情况。

### 相关 Win32 API
1. `SystemParametersInfo(SPI_GETWORKAREA, ...)`
2. `GetMonitorInfo`
3. `GetSystemMetrics(SM_XVIRTUALSCREEN)` 等

### 实现思路
1. 优先基于目标显示器矩形和其工作区信息进行定位。
2. 统一使用虚拟屏幕绝对坐标，避免单屏局部坐标导致偏移错误。
3. 若 `SPI_GETWORKAREA` 仅返回主屏工作区，则以显示器枚举结果中的工作区为目标显示器依据，并将 `SPI_GETWORKAREA` 作为系统工作区行为参考与兼容校验。

---

## 6.5 桌面图标句柄获取与视图访问

### 功能说明
程序需要定位桌面图标所在的 `SysListView32` 并访问桌面视图，从而获取图标数量、遍历图标并修改其位置。

### 用户价值
实现真实的桌面图标坐标重排，而不是伪操作。

### 实现要求
1. 稳定定位桌面 `ListView`。
2. 能获取图标总数和索引。
3. 逐个为所有图标设置新坐标。
4. 不依赖文件系统路径，不操作桌面目录实体文件。

### 相关 Shell / Win32 API
1. `SHGetDesktopFolder`
2. `IShellView`
3. `IFolderView2`
4. `FindWindow`
5. `FindWindowEx`
6. `LVM_SETITEMPOSITION`

### 实现思路
1. 使用 Shell 桌面对象接口确认当前桌面视图上下文。
2. 使用窗口查找获取实际承载图标的 `SysListView32` 句柄。
3. 以 `ListView` 项索引为单位发送 `LVM_SETITEMPOSITION`。
4. 保证“移动图标”仅为修改桌面 `ListView` 中图标坐标，不移动文件、不改快捷方式位置数据。

---

## 6.6 自动执行图标移动

### 功能说明
程序在启动后首次检测到桌面就绪时，自动执行一次图标移动。

### 用户价值
避免用户每次登录后手动点击操作。

### 实现要求
1. 首次就绪时只自动触发一次。
2. 若首次执行失败，允许后续重试机制触发。
3. 自动执行过程写入日志。

### 相关 API
1. `FindWindow`
2. `FindWindowEx`
3. `LVM_SETITEMPOSITION`

### 实现思路
1. 将“Explorer 就绪检测”和“首次自动移动”拆分为两个状态机阶段。
2. 检测到 `SysListView32` 后，调用统一的移动执行器。
3. 记录执行开始、目标显示器、图标数量、成功/失败结果。

---

## 6.7 显示器变化自动重排

### 功能说明
当系统显示器配置变化时，程序自动重新执行图标移动，保证图标始终位于当前目标显示器工作区。

### 用户价值
适配显示器热插拔、分辨率变化、扩展模式切换、主副屏切换。

### 实现要求
1. 接收 `WM_DISPLAYCHANGE`。
2. 触发后重新枚举显示器。
3. 重新确认目标显示器是否仍可用。
4. 执行防抖处理，避免短时间连续多次重排。
5. Explorer 尚未恢复稳定时允许延迟重试。

### 相关 Win32 API
1. `WM_DISPLAYCHANGE`
2. `EnumDisplayMonitors`
3. `FindWindow`
4. `FindWindowEx`
5. `SetTimer`

### 实现思路
1. 隐藏窗口接收 `WM_DISPLAYCHANGE`。
2. 事件到来后不立即连续多次操作，而是启动一个短延迟定时器。
3. 定时器触发时重新获取显示器列表与桌面 `ListView`，确认稳定后执行移动。
4. 若目标显示器消失，按降级规则重新选定目标。

---

## 6.8 图标排列策略

### 功能说明
所有桌面图标需要从目标显示器工作区左上角开始，按列优先方式平铺，间距尽量与系统桌面图标网格一致。

### 用户价值
图标布局整齐，与 Windows 用户认知一致。

### 实现要求
1. 以目标显示器工作区左上角为起始点。
2. 排列方向为列优先。
3. 使用系统图标网格间距或兼容的估算值。
4. 超出一列高度后换到下一列。
5. 保证所有图标都落在目标显示器工作区内部。

### 相关 Win32 API / 消息
1. `LVM_SETITEMPOSITION`
2. `LVM_GETITEMCOUNT`
3. 可选读取网格相关 `ListView` 布局参数
4. 虚拟屏幕坐标：`GetSystemMetrics(SM_XVIRTUALSCREEN)` 等

### 实现思路
1. 获取图标总数。
2. 根据图标网格宽高计算单列可容纳的图标数。
3. 从左上角开始，Y 轴先递增，超出工作区高度后 X 轴前进一列。
4. 坐标统一使用虚拟屏幕绝对坐标，并转换为桌面 `ListView` 接受的位置参数格式。
5. 若无法精确读取系统网格，则采用与常规桌面图标布局一致的保守默认值作为降级。

---

## 6.9 托盘图标与菜单

### 功能说明
程序通过系统托盘提供所有交互入口。

### 菜单项
1. 立即移动图标
2. 设置目标显示器
3. 开机自启 开/关
4. 退出

### 用户价值
无需主窗口即可完成全部操作。

### 实现要求
1. 左键或右键触发托盘菜单策略需统一明确，建议右键弹出菜单。
2. “立即移动图标”触发一次完整移动流程。
3. “设置目标显示器”展开或弹出子菜单，列出当前可选显示器。
4. “开机自启 开/关”显示当前状态并允许切换。
5. “退出”时移除托盘图标并安全结束进程。

### 相关 Win32 API
1. `Shell_NotifyIcon`
2. `TrackPopupMenu`
3. `AppendMenu` / `InsertMenuItem`
4. 自定义 `WM_TRAYICON`
5. `DestroyWindow`
6. `PostQuitMessage`

### 实现思路
1. 程序启动时注册托盘图标和提示文本。
2. 接收到托盘消息后弹出菜单。
3. 菜单命令统一映射到命令处理器。
4. 目标显示器菜单按当前枚举结果动态生成，显示“显示器 1（主屏）”“显示器 2（副屏）”等标识。

## 6.10 设置目标显示器

### 功能说明
用户可从托盘菜单选择图标要移动到哪个显示器。

### 用户价值
在多副屏场景中可控性更强，不局限于默认副屏。

### 实现要求
1. 支持列出当前全部显示器。
2. 默认优先推荐非主显示器。
3. 允许用户显式选择任一显示器作为目标。
4. 选择后立即持久化配置，并可选择立即执行一次移动。
5. 若目标显示器失效，自动降级并记录日志。

### 相关 API
1. `EnumDisplayMonitors`
2. `GetMonitorInfo`
3. 配置文件或注册表持久化 API

### 实现思路
1. 以显示器设备名或稳定标识保存目标显示器。
2. 启动和显示器变化后进行匹配。
3. 匹配失败则回退到首个非主显示器；若不存在则停止移动。

## 6.11 日志系统

### 功能说明
所有关键操作、异常与降级行为写入 `%APPDATA%\IconMover\icon_mover.log`。

### 用户价值
便于排查 Explorer 未就绪、目标显示器丢失、注册表写入失败、图标移动失败等问题。

### 实现要求
1. 日志目录不存在时自动创建。
2. 至少记录时间、级别、操作阶段、错误码、错误描述。
3. 对关键失败使用 `GetLastError() + FormatMessage` 输出可读错误信息。
4. 日志写入失败不应导致程序崩溃。

### 相关 Win32 API
1. `SHGetFolderPath` 或等效方式获取 `%APPDATA%`
2. `CreateDirectory`
3. `CreateFile` / 文件流
4. `GetLastError`
5. `FormatMessage`

### 实现思路
1. 应用启动时初始化日志路径。
2. 关键路径埋点：
   - 启动
   - 托盘初始化
   - Explorer 就绪检测
   - 显示器枚举结果
   - 自动/手动移动开始与结束
   - 注册表写入与删除
   - 退出
3. 错误日志统一封装，确保格式一致。

---

## 7. 业务规则

1. 当仅检测到一个显示器时，不执行移动，仅记录“无可用副屏/目标屏”。
2. 当目标显示器不可用时，自动降级到第一个非主显示器。
3. 当没有任何非主显示器时，保留当前图标位置，不进行重排。
4. 图标移动始终只操作桌面 `ListView` 坐标，不操作桌面文件。
5. 自动执行与手动执行复用同一套移动逻辑。
6. 显示器变化触发的自动重排需要防抖，避免频繁执行。
7. 退出程序后不负责恢复原图标位置。

---

## 8. 技术架构

## 8.1 架构原则
1. 原生 Win32 单进程、轻量后台常驻。
2. 消息驱动架构，避免复杂线程模型。
3. 逻辑模块清晰拆分，便于后续维护和扩展。
4. 所有关键外部交互点必须可日志追踪。

## 8.2 模块划分
1. `App/Bootstrap`
   - 进程入口
   - 配置加载
   - 日志初始化
   - 消息窗口创建
2. `TrayManager`
   - 托盘图标注册与释放
   - 右键菜单构建
   - 菜单命令分发
3. `ExplorerWatcher`
   - Explorer 就绪检测
   - `SysListView32` 查找
   - 重试与延迟机制
4. `MonitorManager`
   - 显示器枚举
   - 主副屏识别
   - 目标显示器解析与降级
5. `DesktopIconMover`
   - 获取图标数量
   - 计算目标坐标
   - 发送 `LVM_SETITEMPOSITION`
6. `AutoStartManager`
   - `HKCU Run` 状态读写
7. `ConfigManager`
   - 保存目标显示器和用户偏好
8. `Logger`
   - 日志格式化
   - 错误码翻译
   - 文件写入

## 8.3 运行流程
1. 进程启动。
2. 初始化日志、配置、托盘、消息窗口。
3. 读取开机自启状态和目标显示器配置。
4. 等待 Explorer 桌面 `ListView` 就绪。
5. 就绪后枚举显示器并执行首次图标移动。
6. 常驻监听托盘命令与 `WM_DISPLAYCHANGE`。
7. 接收到手动或自动触发事件后重复执行移动流程。
8. 程序退出时移除托盘图标并释放资源。

## 9. 关键 Win32 / Shell API 说明

## 9.1 `EnumDisplayMonitors`
用途：枚举系统中的所有显示器。  
在本项目中的作用：构建显示器列表，识别主显示器、候选副显示器、目标显示器坐标范围。

## 9.2 `SystemParametersInfo(SPI_GETWORKAREA)`
用途：获取系统工作区信息。  
在本项目中的作用：辅助理解系统工作区边界，避免图标压到任务栏区域。  
说明：对于多显示器场景，需要结合显示器枚举结果和虚拟屏幕坐标共同使用，不能仅依赖主屏工作区结果。

## 9.3 `SHGetDesktopFolder`
用途：获取桌面 Shell 文件夹接口。  
在本项目中的作用：建立桌面 Shell 视图上下文，辅助访问桌面对象。

## 9.4 `IShellView`
用途：表示 Shell 视图接口。  
在本项目中的作用：关联当前桌面视图实例，为桌面图标视图操作提供上层语义支持。

## 9.5 `IFolderView2`
用途：访问文件夹视图中的项及其状态。  
在本项目中的作用：获取桌面图标项、遍历顺序和视图相关信息，为移动逻辑提供项目级访问能力。

## 9.6 `LVM_SETITEMPOSITION`
用途：修改 `ListView` 中指定项的位置。  
在本项目中的作用：核心图标移动手段，逐个设置桌面图标的新坐标。  
关键说明：这属于桌面图标视图坐标操作，不是文件移动。

## 9.7 `Shell_NotifyIcon`
用途：管理系统托盘图标。  
在本项目中的作用：注册、更新、删除托盘图标，承载用户交互入口。

## 9.8 `WM_TRAYICON`
用途：自定义托盘回调消息。  
在本项目中的作用：接收托盘点击、右键菜单唤起等事件。

## 9.9 `WM_DISPLAYCHANGE`
用途：系统显示配置变化通知。  
在本项目中的作用：触发重新枚举显示器和自动图标重排。

## 9.10 `FindWindow("Progman")` / `FindWindowEx`
用途：查找桌面宿主窗口和桌面图标 `SysListView32`。  
在本项目中的作用：等待 Explorer 就绪并获取桌面图标实际承载控件句柄。

## 9.11 `GetSystemMetrics(SM_XVIRTUALSCREEN)` 等
用途：获取虚拟屏幕整体坐标系。  
在本项目中的作用：处理副屏位于主屏左侧或上侧时的负坐标场景，保证图标定位准确。

## 10. 关键交互与行为定义

## 10.1 首次启动行为
1. 程序常驻托盘。
2. 自动等待 Explorer 桌面视图就绪。
3. 自动将图标移动到默认目标显示器。
4. 写入启动与执行日志。

## 10.2 手动移动行为
1. 用户点击“立即移动图标”。
2. 程序重新获取桌面句柄与显示器信息。
3. 执行一次完整移动。
4. 成功或失败均记录日志。

## 10.3 设置目标显示器行为
1. 用户从托盘菜单选择目标显示器。
2. 程序保存选择结果。
3. 建议立即触发一次图标移动。
4. 若目标屏不可用则提示降级并记日志。

## 10.4 开机自启行为
1. 用户切换“开机自启 开/关”。
2. 程序写入或删除 `HKCU Run`。
3. 菜单状态即时更新。
4. 失败时记录详细错误。

## 10.5 退出行为
1. 用户点击“退出”。
2. 程序移除托盘图标。
3. 停止定时器与消息循环。
4. 记录退出日志。
5. 不恢复图标原始布局。

## 12. 异常处理与降级策略

## 12.1 Explorer 未就绪
风险：程序启动时桌面尚未初始化完成。  
降级方案：使用定时器持续重试查找 `SysListView32`，直到成功或超过合理重试窗口后继续后台等待，不退出进程。

## 12.2 无副屏或目标显示器消失
风险：用户断开副屏、扩展坞断连。  
降级方案：不执行移动；若仍有其他非主显示器则自动切换到首个可用目标；写日志。

## 12.3 `LVM_SETITEMPOSITION` 执行失败
风险：Explorer 状态异常、句柄失效、桌面视图不稳定。  
降级方案：重新获取桌面 `ListView` 句柄后重试一次；仍失败则记录错误并停止本次执行。

## 12.4 工作区或网格参数获取不准确
风险：不同系统配置下图标间距存在差异。  
降级方案：采用保守默认列宽/行高进行排列，优先保证图标全部落入目标工作区。

## 12.5 注册表写入失败
风险：权限异常、路径错误、杀软拦截。  
降级方案：保持当前状态不变，写日志，菜单状态回滚为真实状态。

## 12.6 日志写入失败
风险：目录权限异常、磁盘满。  
降级方案：不中断主流程，仅放弃本次日志写入。

## 12.7 托盘图标丢失
风险：Explorer 重启导致托盘图标失效。  
降级方案：监听任务栏重建消息并重新注册托盘图标。

## 13. 约束条件

1. 本项目必须为全新 C++/Win32 原生项目，从零开始构建。
2. 构建系统固定为 `CMake + MSVC`，目标平台 `x64`。
3. 最低系统要求为 Windows 10。
4. 必须使用以下核心技术栈：
   - `EnumDisplayMonitors`
   - `SystemParametersInfo(SPI_GETWORKAREA)`
   - `SHGetDesktopFolder`
   - `IShellView`
   - `IFolderView2`
   - `LVM_SETITEMPOSITION`
   - `Shell_NotifyIcon`
   - `WM_TRAYICON`
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
   - `FindWindow("Progman")`、`FindWindowEx`
5. 图标移动仅指修改桌面 `ListView` 项坐标，不允许移动桌面文件。
6. 副屏坐标必须使用虚拟屏幕坐标系处理。
7. 所有源文件统一使用 UTF-8 with BOM 编码。
8. 错误处理必须采用 `GetLastError() + FormatMessage`，关键失败必须记录到日志。
9. 日志路径固定为 `%APPDATA%\IconMover\icon_mover.log`。
10. 不生成与项目无关的测试命令或脚本体系。

## 16. 风险清单

1. Explorer 桌面层级在不同系统环境下可能存在差异，导致 `SysListView32` 定位不稳定。
2. 多显示器工作区与虚拟坐标换算处理不当，可能导致图标偏移到错误区域。
3. 图标网格间距无法完全精确获取时，可能出现与用户当前桌面网格存在轻微差异。
4. Explorer 在显示器切换期间可能短暂重建桌面视图，导致句柄失效。
5. 托盘图标在 Explorer 重启后可能丢失，需要补做重注册。
6. 极端环境下第三方桌面管理工具可能与本工具产生冲突。

## 18. PRD结论
IconMover 是一个面向 Windows 多显示器用户的轻量级原生托盘工具，核心目标是在不操作文件系统的前提下，通过桌面 `ListView` 坐标控制，将桌面图标自动或手动移动到目标显示器。产品以稳定、轻量、可常驻、可自动恢复为核心设计原则，基于 Win32 与 Shell API 实现，适合从零开始构建为一个 CMake + MSVC 的 Windows 原生 x64 项目。
